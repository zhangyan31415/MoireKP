# MoireKP 正式计算代码清理计划

**目标：** 删除临时调试残留和过时生产实现，收拢正式入口、数据约定与模块职责，使每一种支持的计算行为都有明确的数学定义、一个生产实现和可随提交重放的验证。

**组织方式：** 使用当前 checkout；按下面的独立批次执行，每批先核对调用方、再修改和验证，分别提交。配置解析负责拒绝不支持的输入，数值核心不猜版本、不自动迁移、不以捕获程序错误的方式切换算法。

**技术栈：** 现有 Python / NumPy / SciPy / pytest、两个现有包 `kp` 和 `tapw`、现有科学数据格式和构建工具。不新增兼容框架、版本注册框架或包揽全流程的大 `Context`。

## 2. 明确边界

- 不增加旧输入兼容层、接口包装、别名迁移或自动版本猜测；各类产物仅接受明确的当前格式，其他格式明确拒绝。
- 不机械删除所有 `vN`、`legacy`、`fallback` 搜索命中。公开名称表达数学方法；必要单位、坐标规范、数据类型和缓存身份仍须明确记录。
- 保留正式支持的 `linear/nonlinear`、`high/low` 行为及其不同目标函数；不同数学问题不能为了去分支而合并。
- 保留独立的 Reynolds 数学参考和直接原子投影参考。参考实现不能与被测生产实现共享关键相位推导后再声称独立验证。
- 只有明确选择的、计算同一个数学对象的数值后端可以并存；适用条件写清楚。认证失败或程序错误不能触发隐式换算法。
- 不通过增加容差、改变秩门限、改变物理支持范围或改变验收参考来使清理通过。
- 按用户要求，不处理 NaN 问题；不处理已撤回的“零轨道扇区被检查”反例。
- 暂不增加 S/Löwdin 验证，不处理倒空间逆转置调整，不扩展空间群或旋转轴框架。
- 仅移除被确认无用的源码和打包条目；不执行宽泛 `git clean/reset`，不清理其他任务的文件或进程。
